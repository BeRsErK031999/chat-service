# Chat Beta Triage

## Categories

`Critical`

Blocks chat usage or prevents testing from continuing.

Examples: chat does not open, no rooms are available for all testers, messages cannot be sent by any tester, app becomes
unusable after opening chat.

`Major`

Strongly interferes with normal testing, but there is a workaround.

Examples: messages are delayed often, unread state is misleading, room switching breaks after a sequence of actions,
ActivityPanel is hard to use for a core scenario.

`Minor`

Inconvenience, confusing behavior, visual issue, wording issue, or small improvement.

Examples: unclear label, one-off layout issue, inconvenient focus behavior, minor keyboard navigation problem.

`Idea`

Suggestion for a future version.

Examples: new message action, extra notification option, integrations, advanced room behavior.

## Process

Do not fix issues immediately from the feedback thread.

1. Collect feedback during the beta window.
2. Ask short clarifying questions only when a report cannot be understood.
3. Group duplicates by scenario and severity.
4. Confirm which items are launch blockers.
5. Decide what to fix now, what to defer, and what to reject.
6. Create implementation tasks only after grouping and decision.

Use [Chat Beta Feedback Template](./chat-beta-feedback-template.md) for incoming reports.
